    Method
    
Each harness runs on its own VM (2 vCPU / 8 GB) and does the task through its own native tools, pinned by version and checksum. The scripted model answers locally, so a run measures what the harness costs, not how well a model codes. An agent passes only if it exits cleanly, changes only allowed files and passes tests it never saw. Every run is sealed and verifiable.

    
Harness packs have two paths on the same files. The naive path is one tool call at a time. One program writes the same files in a single step. A pass on either path is conformance to that script. Before each run, the lane checks that its machine is quiet, then runs mini three times at one agent: the control. Startup, step gap and CPU are printed as a ratio to the lane's own control (×4.2 ctl), because a slower machine scales time. Memory and disk are not scaled. A series repeats the race 6 times; each dot is one repetition, and two harnesses are called tied when the 95% bootstrap interval of their paired difference includes 0. Numbers are shaded only when the best and worst differ by at least 10%, and each lane says which harnesses it was compared with. mini is the floor and stays off the ranking.

    
Memory in use is what all of a lane's agents hold together: the anonymous memory, mapped files and kernel memory of the runner's control group, less the runner's own and what was there before the first agent started. Shared pages count once, so it cannot exceed the machine. Memory per agent is that figure divided by the agents alive, at the moment most were alive. Largest process is the biggest single process of each agent (kernel rusage); a harness of several processes holds more than that. CPU is the whole machine, the runner's own setup and checks included. Disk is what the agent itself wrote to its sandbox between launch and exit; the runner's setup (the task's files, the adapter's config, a prepared home) and the checker's copy are not counted. Startup is launch to first model request, over the agents that made one. Step gap is one reply sent to the next request. Context growth is bytes per step after the first request. Wall is the swarm itself, first launch to last exit, without the plan freeze and verification around it; passed per VM-hour divides by it. That rate is blank when the wave did not fill or agents waited to be admitted.

    
An attempt that never ran, because the runner could not set it up (a full disk, a failed copy), stopped it, or never admitted it for lack of room, is counted as not run, never as a failure of the harness; “half passed” is counted of the attempts that ran. Before each launch the runner checks free disk as well as memory, and holds the launch when there is not room. After every run the machine is reset and checked (sandboxes removed, leftover processes stopped, disk and memory back near idle); a lane that is not clean takes no race.

    
Real models go through a Swarm gateway, run by the operator and labelled. Claude Code runs Claude models, Codex runs OpenAI models; the Claude sign-in route is given only to the Claude Code lane, so other harnesses use Claude through the API.
